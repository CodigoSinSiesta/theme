Hands-on · 25 min ⭐

Levantar una skill desde cero

Sin magia. Cuatro comandos y un agente que entiende tu repo.

~/proyecto · zsh
clonamos el starter
~git clone css/skill-starter mi-skill
Cloning into 'mi-skill'... done.
~cd mi-skill && pnpm install
Packages: +42 Done in 4.1s
arrancamos en watch
~pnpm dev --watch
✓ skill 'graphify' registered
✓ listening on /q trigger
~claude /q '¿dónde definimos auth?'
→ src/auth/index.ts:42
→ src/middleware/jwt.ts:18
Narración paso a paso
1
Clonamos el starter — todo el scaffolding ya está.
2
pnpm install — solo deps, sin globals.
3
Editamos skill.ts — describe + run, nada más.
4
El agente la descubre vía MCP y la usa con /q.
💡
Pro tip
Si la skill no aparece, revisa el campo trigger. Es la pista #1 que olvidamos.

Componentes · Callouts

Cuatro acentos semánticos

Mismo layout, cuatro colores. Info para tips, ok para success, warn para precauciones, err para anti-patterns.

💡
Pro tip
Si la description ocupa más de 2 líneas, divide en dos skills. La concisión es contrato.
✓
Lo que mejora
Identidad de engineering deck más fuerte. Mejor contraste para code y terminal. Menos ruido visual.
⚠️
Cuidado
Los benchmarks miden tareas pequeñas. Mantenibilidad a 6 meses no aparece en estos números.
✗
Anti-pattern
Mega-prompt monolítico que delega todo. Frágil, no testeable, y opaco cuando algo falla.
